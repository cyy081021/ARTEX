# 跨设备接入向导：更新与验证记录

日期：2026-11-10。本次为 main 分支功能更新，不创建版本 tag。

## 2026-11-11 网络变更恢复修复

实机只读检查发现：保存的 Windows IP 与当前网卡地址不同，旧桥接仍使用原地址；Windows 网卡检测一次耗时约 9 秒，超过原 5 秒限制，启动环境中因而缺少 Windows 网卡。原“刷新状态”仅返回启动时缓存，不能恢复地址检测。

修复增加管理员显式重新检测接口，预览/确认时重新校验当前网络，环境变化使旧方案失效；接口顺序变化不会误使方案失效。普通 GET 轮询不执行系统命令。前端更新失效地址及关联网段，检测恢复后自动预填 Windows 地址，并保留有效的手工选择。Windows 检测超时调整为 15 秒。

验证：`go test -race ./teamsetup -count=1` 通过，覆盖刷新不监听/不落盘/不中断已启用入口、旧计划失效、地址顺序稳定、切片隔离和外部 CLI 拒绝。独立 PostgreSQL 上 `go test -race ./server -run 'Test(Onboarding|TeamListenerTLSScopesMemberAccess)' -count=1 -v -timeout 3m` 通过，覆盖成员拒绝刷新、GET 不检测、确认前网络变化拒绝应用和原隔离/AI 边界。

4 项前端地址恢复测试和 `npm --prefix web run build:static -- --webpack` 通过。浏览器合成夹具重现启动时缺失 Windows 网卡的错误，再通过真实刷新接口取回 Windows 候选、预填新 IP/网段并成功生成新方案；验收未点击应用，不修改主机网络或运行真实任务。

此修复不自动更改已授权的监听地址、来源网段、Windows 桥接或证书信任。网络变化后的新方案仍由管理员确认；真实双机可达性须在成员端重新验证。

## 更新内容

- 团队页加入接入向导：检测主端地址、预填网段、预览固定方案、明确确认后开启受限 TLS、下载成员接入包和一次性配对、定期核对设备状态。详细手工 LAN/Relay 配置保留。
- 受管成员 TLS 动态启停，主端任务引擎不重启。启动参数管理的 TLS/Relay 入口保持原有行为。证书和状态安全持久化，端口占用、TLS 检查或写盘失败时关闭新入口。
- AI 用无工具的单次调用解释固定检测事实。拒绝自由日志输入，不发送设备地址、私钥、身份或模型密钥；输出有大小/结构限制，失败时回退固定建议。
- `artex-node setup` 完成证书/版本核验、本地配置、单次配对和身份复用，保留既有配置。可生成渗透或逆向的独立无外部工具角色模板；密钥仅进入进程环境；启动执行需再次明确确认。
- 正式构建新增五种 Node 资源与版本/SHA256 清单。成员包不含配对码、私钥和模型凭据。WSL 的固定桥接脚本默认预览，实际操作限定选定 IP、端口和来源网段。

## 多机验证仍需实测

本次没有第二台物理设备。以下不作为已通过项目：真实 LAN 互通、Windows 主机桥接的实际应用、跨网 Relay、macOS/ARM 的实际运行，以及具体模型/MCP 工具执行。
