# 团队自动协作

团队首页用于查看共享任务、成员和设备。点击任务名称进入独立任务页，默认打开会话；协作进度、待复审记录和任务概览分别查看。

## 开始使用

1. 成员更新并启动配套的 `artex-node`，主端为成员授予此任务的查看、执行权限。模型凭据和工具仍使用成员设备自己的配置。
2. 打开任务的“协作进度 / 执行”，在暂停状态下点击“自动生成协作方案”。目标、已登记的资产范围、约束和材料从主任务读取，设备能力由 Node 的配置检查报告匹配。
3. 核对方案，点击“确认配置并启用协作”，然后点击“开始协作”。无需填写能力键，也无需逐项手动发布、选择执行设备。
4. 在会话页查看“协作调度”和各工作分支，可按设备编号识别执行端，并发送指导调整方向。明确的结果自动接收，存在疑点的结果进入人工复审。

默认开启自动拆分和派发、候选工作自动发布、明确结果自动接收。预算、时限及这些开关放在高级设置；关闭自动发布后，协调器的候选工作需要管理者批准才能派发。

## 运行逻辑

开始协作后，系统建立一个独立的协调分支。它复用相应流程 Planner 的模型配置，但使用独立会话和协调指令，只能提出工作、发布工作、等待结果，不执行工具工作单。每个子工作自行绑定资产、材料、工具需求、依赖和预算。

调度器从已确认的设备中匹配角色及工具能力，给空闲设备分配工作；没有合适设备时工作留在队列。每台设备最多接一个未结束的执行分支，协调分支不占这个名额。不同设备拿到各自的工具配置，不会因工具能力并集而要求每台机器安装所有工具。设备失联后不会直接把可能仍在执行的工作复制到另一台机器；可在高级管理中处理交接。

执行角色与核验角色使用不同会话。核验结果记录明确判断、依据、验收是否满足以及所检查的证据版本。判断为可接收、版本对应且有执行证据时，系统自动接收并保留理由；核验存在疑点、结果冲突或缺少判断时转人工复审。自动接收不伪造人工复核人，也不自动宣布主任务完成。

已接收的分支及证据版本继续作为依赖使用，无需因为它来自另一台设备而再套一层人工审批。证据变更仍使用原有失效、补充和复核流程。

## 配置与兼容

- 自动方案读取当前主任务自己的范围，不把其他任务、发现线索或目标描述中出现的任意地址自动变成执行授权。需要调整目标时，在主任务里维护范围，再刷新方案。
- Node 上报的是模型、环境变量、工具映射、范围字段和运行时配置检查结果；生成预览不调用外部模型或工具。缺少配置会在设备卡片中显示原因。
- 预览绑定任务、当前操作人、选项、设备和权限。启用时重新核对；内容变化后刷新方案即可，无需重填。
- 旧手动策略和旧 Node 的原有执行接口保持兼容。自动配置需要配套的新 Node 报告；仅更新网页不能替成员机器更新程序。
- 动态观察仍使用现有运行环境和材料绑定。自动调度不会新增环境凭据或扩大任务范围。
- 无数据库表结构迁移。新字段随项目策略 JSON 保存；旧项目不会被静默切换为自动调度或自动接收。

## 验证

本轮使用隔离数据库、合成任务和本机逻辑设备验证，不访问真实测试目标。验证内容包括预览无副作用、确认过期或来源变化拒绝、不同设备分别获得自己的工具、多次同时轮询不重复派发、暂停不执行，以及明确结果自动接收/不明确转人工。

具体命令、真实 Node 与本地模拟模型结果、浏览器验收和本机换装记录见本轮发布说明。该更新先进入 `main`，不创建新 tag。
