# 开源与闭源软件审阅

在 **任务 → 新建任务** 填写对象和审阅目的。公共 GitHub 仓库主页会切换到开源软件，常见发行包文件名（例如 `demo.exe`）会切换到闭源软件。ZIP 既可能是源码，也可能是发行包，可手动选择场景。任务页的“软件档案”区域可以重新打开记录或恢复导出的 JSON。

| 场景 | 可导入的材料 | 可以核对的结果 |
| --- | --- | --- |
| 开源软件 | 公共 GitHub 仓库及可选分支、标签或提交，本地源码目录、文件或 ZIP，可附发行包 | 远端解析出的提交、实际源码树的 SHA-256、相对路径、文件摘要及引用行号 |
| 闭源软件 | 一个或多个发行包，可补充已有日志 | 每份原包的 SHA-256、ELF 或 PE 头部识别、ZIP 内组件到父包的对应关系 |
| Web、逆向 | 使用原任务表单和已有材料入口 | 原任务详情、历史和归档。显式 Web 选择走已有分类器，新软件档案单独保存 |

### 审阅与导出

1. 打开档案，在“材料与来源”中选择文件。文本材料支持预览和行号引用，原材料可以下载。
2. 可附加已有证据，并填写证据对应的源码快照或发行包 SHA-256。登记观察时可选择适用版本。服务端核对引用的材料、摘要和行号，拒绝把其他版本的证据登记到所选版本。
3. 保存源码观察、已有运行记录、反证或待确认事项。点击引用可返回原文件。多人同时编辑同一修订时，后提交的页面会收到冲突提示，可刷新后重试。
4. 文本报告包含材料、观察和引用。完整 JSON 归档同时保留材料字节、修订号和校验和，可在另一套有相同功能的单机实例中恢复。重复导入相同归档会返回原档案。

### 支持范围

每份档案累计最多 4096 个文件和 32 MiB 材料，原 ZIP 和解出的内容均计入限额。ZIP 只读取常规文件。公共仓库导入使用 GitHub 的匿名 HTTPS 接口；私有仓库和其他托管服务可通过本地源码目录或 ZIP 导入。

本地目录保存浏览器实际提供的工作树文件，跳过 `.git`。用户填写的基线提交属于声明信息。工作树快照由排序后的相对路径和文件摘要计算，同一提交上的未提交修改会得到独立快照。

软件场景处理已有材料和证据。运行记录需要由审阅者提供。工具可见性仅表示命令是否出现在服务进程的 PATH 中。原版 Web 和逆向任务继续使用各自的详情与归档入口。

### 验证方法

运行 `go test ./dossier` 检查源码快照、引用和 ZIP 组件的完整性。使用独立的测试 PostgreSQL 数据库运行 `go test ./server -run '^TestExplicitWebScenarioWaitsForMaterials$' -count=1`，可检查显式 Web 选择、旧分类器响应以及等待材料的状态。
